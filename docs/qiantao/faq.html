QianDao · 常见问题

说实话，九成的问题出在两件事上：版本不对，或者改完没重载。先排除这两条，再看下面的分类。

安装与启动

插件名显示红色 / 加载失败

  • 确认服务端是 1.12.2，核心是 Spigot 或 Paper
  • 确认 Java ≥ 8
  • 看控制台完整报错。Unsupported class file major version 是 Java 太低，NoClassDefFoundError 通常是核心版本不匹配
  • jar 下载不完整也会这样，重新下一遍最快

启动后没有生成 config.yml

先确认插件真的加载了 —— 控制台应该有 QianDao 签到插件已启用。如果没这行，就是 jar 没被识别；如果有这行但没文件，检查 plugins/ 的写权限。

签到与奖励

签到成功，但金币没到账

按顺序查：

  1. 启动日志里 金币联动: 后面是什么。已关闭 就是没检测到前置
  2. economy.type 写的是不是已安装的那个（zpoints / playerpoints / vault）
  3. 前置装好后执行 /qd reload，再签一次

金币不到账不影响物品奖励，这两条线是分开的。

改了奖励物品，游戏里没变化

  • 有没有执行 /qd reload
  • cycle 对应天的 commands 写对没有，%player% 不能丢
  • 指令是控制台执行的，看看控制台有没有报「未知指令」—— 很可能是某个指令插件没装

第 8 天为什么回到第 1 天奖励

设计如此。7 天一个周期，第 8 天从第 1 天重新开始，但连续天数继续累计，所以里程碑（7 / 14 / 30 天）照常触发。

连续天数突然归零

连续链必须以「今天」或「昨天」结尾。超过一天没签，就判定为断签，连续天数归零，里程碑记录也重新算。这是签到插件该有的严格，不然补签卡就没意义了。

补签

补签面板里没有可选日期

补签只列出同时满足三个条件的日期：

  • 最近 buqian.max-days 天内
  • 在该玩家首次签到之后
  • 当天既没正常签到，也没补签过

新玩家没有历史记录，自然一个都没有。

补签卡从哪来

三个来源：在线奖励（online-reward）、管理员 /qd givecard <玩家> [数量]、活动发放。

补签了，连续天数还是没接上

补签只能补「断掉的那一天」。如果断了三天，只补一天接不上整条链，得把中间几天都补了。

排行榜

右侧计分板不显示

  • ranking.scoreboard-enable 是不是 true
  • 有没有被别的计分板插件顶掉（称号、状态、任务类插件最容易冲突）
  • /qd reload 会给在线玩家重建计分板，试一次

某个人不在排行榜上

从未签到过的玩家（连续 0、累计 0）不上榜，这是有意为之，避免新服排行榜全是零。

配置与升级

升级后配置项丢失 / 报错

删掉 plugins/QianDao/config.yml 让插件重新生成，再把自定义内容迁回去。升级前备份是前提，见 安装部署。

能热重载吗

/qd reload 可以，会重载配置、重新初始化经济联动、重建计分板。

但不建议用插件管理器整体重载本插件 —— 定时任务会重复注册，表现为在线奖励发得越来越快。

支持 1.13 以上吗

当前构建面向 1.12.2，材质名（如 SKULL_ITEM:5）和音效名都是 1.12.2 的。需要其他版本走 插件定制。

数据

数据存在哪

plugins/QianDao/data.yml，以玩家 UUID 为键，存签到日期、补签日期、累计次数、已发里程碑、在线统计。

怎么备份 / 迁移

复制 config.yml 和 data.yml 到新服务器的同名目录。UUID 不变，数据就通用。

文件会不会越来越大

不会。超过 60 天的日期记录会自动清理，累计次数和里程碑记录保留。
